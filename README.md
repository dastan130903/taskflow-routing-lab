# Taskflow 2.0 — React Routing & Application Architecture

Extension of the original **react-effects-lab** task manager. Uses the original Fake API and same `localStorage` key, so existing user tasks remain available in the same browser/origin.

## Start

```bash
npm install
npm run dev
```

Open the localhost address printed by Vite (often `http://localhost:5173`).

## Routes

- `/` Home with local SVG illustration
- `/about` About the project
- `/items` list with search, status + priority + category filters, sorting and pagination; query parameters persist in the URL
- `/items/:id` dynamic details with 8 fields and CRUD actions
- `/dashboard` API statistics with interactive category filter and 3 breakdowns
- `/login` nonfunctional authentication placeholder (explicitly indicated)
- `*` custom 404 page

## Structure

- `src/App.jsx` **routing only**
- `src/components/RootLayout.jsx` layout, navigation (`NavLink`), nested route `Outlet`
- `src/components/TaskCard.jsx`, `TaskForm.jsx`, `StatusMessage.jsx` reusable components
- `src/pages/` page components
- `src/hooks/useItems.js` reusable list loading and effect cleanup
- `src/services/service.js` original Fake API CRUD implementation; Promise delays, error handling and localStorage persistence
- `src/styles/` styles

## Preserved features

Create, read, update, delete, complete and reopen tasks; asynchronous list + details, retry, loading/error/empty/success states, reload, persistence, `useEffect` cleanup, stale response protection and identity-safe async actions.

## Key requirements

- Dynamic routes via `useParams`, filtering via `useSearchParams`
- `React.lazy` + `Suspense` for five pages
- BrowserRouter client-side navigation, Back/Forward and deep URLs
- Fake API data, not hardcoded dashboard results
- Responsive design

## Build

```bash
npm run build
npm run preview
```

## Deployment

Deploy to Netlify or Vercel, build command `npm run build`, output folder `dist`. `public/_redirects` and `vercel.json` support refreshing a nested URL.

## Submission

Submit both **your GitHub repository URL** and **deployed application URL** using the course submission page. Neither is generated by this ZIP; you must upload/deploy the project.
